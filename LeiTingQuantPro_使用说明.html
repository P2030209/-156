LeiTingQuantPro 全功能作战手册（完整版）

这是一份按“培训教材”标准整理的手册：分级教学、界面编号、逐控件说明、逐策略模板、逐故障处理，目标是让新手也能按步骤独立完成配置、运行和排障。

0.1 通俗速读版（先看这个就能用）

  • 你要做什么？：先能连上OKX看行情 → 再能安全下单 → 再跑策略 → 最后再上AI与实盘。
  • 你该点哪里？：配置在 文件→系统配置；启动在 1区；看行情在 2区；看挂单在 3区；看报错在 底栏。
  • 什么算成功？：2区价格/K线在动；3区挂单能看到变化；底栏没有连续报错。
  • 真盘怎么开？：顶栏切实盘 + 系统配置里取消模拟交易 + 选“已接入实单策略”启动（详见第 4.5 章）。
  • 最容易踩坑：选了 AI-ALGO 会提示“未接入实单”；那不是坏了，是保护机制（用 AI-LIVE 才能AI真盘）。

0. 界面定位编号（统一语言）

一句话：把界面分成“1区调参数、2区看行情、3区看挂单”，你就不会迷路。

  • 1区（左）：策略下拉、参数组、风控组、启动/停止。
  • 2区（中）：引擎状态、行情识别、K线周期、实时价格、复盘。
  • 3区（右）：订单簿、资产摘要、快捷下单、当前挂单。
  • 顶栏：交易对、模拟/实盘、代理、AI状态、连接状态。
  • 底栏：日志输出与关键字过滤。

1. 分级教程A：新手（目标：跑通不出错）

一句话：新手只做一件事——先用模拟盘把“能看行情 + 能挂单 + 无连续报错”跑通。

步骤A1（顶栏）确认模式与交易对

  1. 模式先选“模拟盘”。
  2. 交易对先用流动性高的合约（建议 ETH-USDT-SWAP）。

步骤A2（文件菜单）完成系统配置

  1. 打开 文件 → 系统配置。
  2. 依次填写：API Key / Secret Key / Passphrase。
  3. 勾选模拟交易，点“测试连接”。
  4. 网络不通时填本机代理（如 http://127.0.0.1:7890），再保存。

步骤A3（1区）启动 PMM 保守模板

  1. 1区策略选 PMM。
  2. 填：spread_bps=50、refresh_ticks=8、order_size=0.001。
  3. 点 启动策略。

步骤A4（2区+3区+底栏）验证三件事

  1. 2区：实时价格变化、K线不冻结。
  2. 3区：挂单列表有新增/撤销动作。
  3. 底栏：无持续报错（连续 3 次及以上同类错误视为异常）。

2. 分级教程B：进阶（目标：提升稳定性和收益质量）

一句话：进阶只做两件事——加风控约束（PMM+）+ 用模板/AI把有效参数沉淀下来。

步骤B1（1区）升级 PMM+

  1. 切换 PMM+，增加 max_inventory 与 slippage_pct 约束。
  2. 建议先用均衡模板跑 2~4 小时，再决定是否提速。

步骤B2（工具）AI 策略助手调参

  1. 打开 工具 → AI 策略助手。
  2. 让 AI 输出 PMM 建议参数，写回1区。
  3. 观察 30~60 分钟成交节奏与撤单比率。

步骤B3（工具）导出模板沉淀

  1. 导出“ETH-均衡模板”“BTC-保守模板”等。
  2. 建立策略模板命名规则，避免覆盖混乱。

3. 分级教程C：实盘（目标：可控上线）

一句话：实盘不是“点一下就上”，而是“保守小仓位上线 + 严格值班检查 + 异常立即停”。

步骤C1（上线前硬检查）

  1. 模拟盘连续稳定 >= 1 天。
  2. 确认 API 权限、交易账户资金、网络稳定。
  3. 确认已准备“紧急停机”流程（停止全部策略 + 撤单）。

步骤C2（1区）先保守再放开

  1. 开启余额压缩、名义上限、杠杆上限。
  2. 首日只用保守模板和小仓位。
  3. 无异常再切均衡模板。

步骤C3（3区+底栏）盯盘规则

  1. 重点盯“挂单是否积压”和“撤单是否失败”。
  2. 连续异常先停，不在异常状态下硬调参数。

4. 全策略推荐初始参数模板（保守 / 均衡 / 激进）

一句话：模板就是“默认起跑线”，先保守跑稳，再逐步切到均衡/激进，别一上来就激进。

4.1 PMM

  • 保守：spread_bps=50，refresh_ticks=8，order_size=0.001
  • 均衡：spread_bps=30，refresh_ticks=5，order_size=0.002
  • 激进：spread_bps=18，refresh_ticks=3，order_size=0.003

4.2 PMM+

  • 保守：spread=45，refresh=8，max_inventory=0.005，slippage_pct=0.30
  • 均衡：spread=28，refresh=5，max_inventory=0.010，slippage_pct=0.50
  • 激进：spread=18，refresh=3，max_inventory=0.015，slippage_pct=0.80

4.3 PMM-NEURAL

  • 保守：spread=40，refresh=8，order_size=0.001，use_talib=off
  • 均衡：spread=25，refresh=5，order_size=0.002，use_talib=on
  • 激进：spread=16，refresh=3，order_size=0.003，use_talib=on

4.4 AI-LIVE

  • 保守：ai_interval=45，max_notional=15，min_conf=0.70，depth_frac=0.20
  • 均衡：ai_interval=30，max_notional=30，min_conf=0.55，depth_frac=0.30
  • 激进：ai_interval=15，max_notional=60，min_conf=0.45，depth_frac=0.40

4.5 AI-ALGO（承载策略）

  • 保守：优先 rule_based，动作少、频率低、单笔名义低。
  • 均衡：rule_based + parameter_optimize 组合，手动审核后上线。
  • 激进：python_code 仅建议模拟盘长测后实盘。

4.6 GRID

  • 保守：band=0.8%，levels=5，size=0.001，refresh=45s
  • 均衡：band=1.2%，levels=7，size=0.002，refresh=30s
  • 激进：band=2.0%，levels=9，size=0.003，refresh=20s

4.7 DCA

  • 保守：interval=600s，size=0.001
  • 均衡：interval=300s，size=0.002
  • 激进：interval=120s，size=0.003

4.8 TWAP

  • 保守：total=0.01，slices=20，interval=60s
  • 均衡：total=0.02，slices=12，interval=30s
  • 激进：total=0.03，slices=8，interval=15s

4.9 ARBITRAGE（监控型）

  • 保守：threshold=30bps，interval=20s
  • 均衡：threshold=20bps，interval=15s
  • 激进：threshold=12bps，interval=8s

4.10 TREND（占位）

当前仍为占位策略，三档模板仅供将来扩展，不建议实盘启用。

4.5 真盘交易开启（重点新增）

一句话：真盘=顶栏切实盘 + 系统配置取消模拟 + 选“已接入实单策略”启动；选错策略会被保护拦住。

4.5.1 开启实盘的标准流程

  1. 顶栏把模式切到 实盘（会弹二次确认）。
  2. 进入 文件 → 系统配置，填实盘 API，取消“模拟交易”勾选，测试连接成功后保存。
  3. 1区选择“已接入实单”的策略，再点 启动策略。
  4. 到3区挂单页确认真实挂单变化，到底栏确认下单/撤单回报。

4.5.2 当前可实单策略与限制

  • 可实单：PMM、PMM+、PMM-NEURAL、AI-LIVE、TWAP、GRID、DCA。
  • ARBITRAGE：当前仅日志监控。
  • AI-ALGO：当前会弹“策略未接入”，不走真实下单通道。
  • TREND：占位策略，不建议实盘。

4.5.3 你截图弹窗的含义

当你选择 AI-ALGO 并启动时，系统会提示“当前仅为代码骨架，不会产生真实订单”。这是保护机制，不是报错。

4.5.4 如果你要 AI 真盘

  • 当前建议用 AI-LIVE：工具菜单开启“启用 AI 实盘决策（AI-LIVE）”，然后1区切 AI-LIVE 启动。
  • 先用保守模板：ai_interval=45、max_notional=15、min_conf=0.70。

4.6 实时盯盘操作（看得懂、用得上）

一句话：盯盘=确保行情在刷新（2区在动）+ 盯挂单与撤单（3区）+ 异常就按 SOP 先停再查。

4.6.1 盯盘前置条件（不满足就先别盯）

  • 2区必须在动：实时价格有变化、K线不冻结。
  • 顶栏连接要正常：连接状态不是长期“—”，延迟不持续异常。
  • 如果不动：先检查代理（顶栏“应用”）或到 文件 → 系统配置 点“测试连接/保存”。

4.6.2 盯盘时“看哪里”（按区域）

  • 2区（中）看：价格跳动、K线刷新、状态线是否异常。
  • 3区（右）看：当前挂单是否积压、撤单是否失败、订单簿是否异常跳变。
  • 底栏看：是否出现连续重复报错（连续3次算异常）。

4.6.3 盯盘时“怎么操作”（最常用 6 个动作）

  1. 只停当前交易对：在 1区 点 停止并撤单。
  2. 紧急总停：在 3区“当前挂单”页点 停止全部策略。
  3. 快速撤单：在 3区点 一键撤单（或“撤全部”）。
  4. 手动补单/纠偏：在 3区“快捷下单”输入价格/数量，点买入/卖出。
  5. 换交易对盯盘：顶栏改交易对后，先观察 1~2 分钟确认刷新正常再操作。
  6. 调参纪律：一次只改 1~2 个参数，改完至少观察 20~30 分钟再继续。

4.6.4 盯盘的“成功标准”

  • 2区行情一直在刷新。
  • 3区挂单能增删变化，撤单大多数能成功。
  • 底栏没有持续刷屏的同类报错。

4.6.5 盯盘异常怎么处理（直接照做）

  • P1（严重）：先 停止全部策略 → 一键撤单 → 切模拟盘 → 导出/截图日志。
  • P2（中等）：先降风险：提高 refresh_ticks、提高 min_confidence、降低 max_notional。
  • P3（轻微）：先观察记录，别立刻大改参数。

4.6.6 最容易踩坑（你截图那种）

  • 选了 AI-ALGO 会提示“策略未接入”，不会走真实下单通道，所以你盯不到“真实成交动作”。
  • 要 AI 真盘盯盘并自动决策：用 AI-LIVE（并开启“启用 AI 实盘决策”）。

5. 逐控件字典（你点到哪，都知道干什么）

一句话：不知道下一步点哪里，就按“顶栏换品种/模式，1区启停与参数，3区下单与撤单，底栏查报错”。

5.1 顶栏

  • 交易对：决定行情、挂单、策略 instId；切换后建议重新观察 1~2 分钟。
  • 模式：模拟/实盘；切实盘会弹确认框。
  • 代理输入 + 应用：运行时临时改网络出口，输入错误会提示。
  • AI状态：off/analyzing/ok/error/paused。
  • 连接状态：REST 延迟与连接状态。

5.2 1区按钮

  • 启动策略：按当前参数实例化并启动。
  • 停止并撤单：停止当前交易对并撤挂单。
  • 预设下拉：快速套参数（保守/均衡/激进）。

5.3 3区按钮

  • 买入/卖出：快捷限价单。
  • 撤全部：当前交易对撤单。
  • 一键撤单：挂单页全撤。
  • 停止全部策略：全局总停。

7. 操作脚本（开机到停机）

一句话：把操作当成“流程”，按顺序做，别跳步；这样出问题也更容易定位。

  1. 开机：检查代理和 API 连接。
  2. 运行前：顶栏选交易对，1区确认模板。
  3. 运行中：2区看行情、3区看挂单、底栏看错误。
  4. 调参：一次只改 1~2 个参数，避免无法归因。
  5. 停机：先“停止策略”，再确认挂单清空。
  6. 复盘：导出模板、记录当日参数和异常时间点。

8. 参数词典（定义 / 范围 / 默认 / 调参影响 / 误配 / 修正）

一句话：你只要记住“范围别越界、一次只改1~2个、改完观察”，就不会越调越乱。

8.1 PMM / PMM+ / PMM-NEURAL 核心

  • spread_bps：定义=总价差；范围=1~2000；默认=20。调大：成交变慢但更稳；调小：成交更快但滑点风险升。误配：过小导致高频撤单。修正：先回到 30~50。
  • order_size：定义=单笔数量；范围=大于0；默认=0.001。调大：收益/风险同步放大；调小：更稳更慢。误配：过大触发保证金不足。修正：先减半并观察 30 分钟。
  • refresh_ticks：定义=刷新秒数；范围=1~3600（GRID 最低建议 5）；默认=3。调大：撤单少更稳；调小：更灵活但更容易限频。误配：太小导致撤单失败增多。修正：调到 5~10。
  • max_inventory（PMM+）：定义=净持仓上限；范围>0；默认=0.01。调大：库存风险上升；调小：更保守。误配：太大导致单边持仓积累。修正：先设 0.005~0.01。
  • slippage_pct（PMM+）：定义=可接受滑点%；范围=0.01~10；默认=0.5。调大：更易成交但成本上升；调小：更保守但可能挂单难成交。误配：太大追价。修正：回 0.3~0.8。

8.2 AI-LIVE 核心

  • ai_interval_sec：定义=AI调用间隔；范围=5~7200；默认=30。调大：成本低更稳；调小：响应快但抖动增。误配：过小导致频繁调用。修正：先 30~60。
  • max_notional_usdt：定义=单笔名义上限；范围=1~1e7；默认=30。调大：风险放大；调小：更安全。误配：过大导致连续亏损放大。修正：先 15~30。
  • min_confidence：定义=最低置信度；范围=0~1；默认=0.5。调大：过滤更多信号；调小：交易更频繁。误配：太低导致噪音单。修正：设 0.55~0.70。
  • price_band_pct：定义=相对中间价偏离上限%；范围=0.05~50；默认=0.5。调大：允许更远挂价；调小：更贴盘。误配：太大导致成交价劣化。修正：0.3~1.0。
  • ai_depth_frac：定义=单笔占对手一档深度比例；范围=0.05~1；默认=0.30。调大：成交更快但冲击更大；调小：更平滑。误配：太大吃穿盘口。修正：0.2~0.35。
  • ai_slip_bps：定义=盘口放宽基点；范围=0~50；默认=1。调大：更易成交但成本增；调小：更严。误配：过高引起追价。修正：1~5。
  • ai_fill_conf_market：定义=低置信度改市价阈值；范围=0~1；默认=0.8。调大：更少市价；调小：更多市价。误配：过低导致市价过多。修正：0.75~0.9。

8.3 GRID / DCA / TWAP / ARBITRAGE

  • grid_band_pct：定义=网格带宽；范围=0.2~25；默认=1.0。调大：覆盖更宽；调小：更密集。误配：太窄导致频繁重挂。修正：先 0.8~1.5。
  • grid_levels：定义=网格档位数；范围=3~21；默认=7。调大：挂单更密；调小：更稀疏。误配：过大导致管理压力升。修正：5~9。
  • dca_interval_sec：定义=定投间隔；范围=10~86400；默认=120。调大：交易更慢；调小：更密集。误配：过小在波动时追涨。修正：120~600。
  • twap_slices：定义=拆单笔数；范围=2~500；默认=10。调大：冲击更低；调小：执行更快。误配：太小冲击大。修正：8~20。
  • arb_threshold_bps：定义=套利提示阈值；范围=1~500；默认=15。调大：信号更少；调小：噪音更多。误配：太小告警刷屏。修正：15~30。

9. 参数联动图谱（调参决策树）

一句话：先按“症状→调参顺序”走，别凭感觉乱改；越乱改越难恢复。

9.1 症状 -> 调参顺序（先后有严格顺序）

  • 症状A：成交太少 -> 先降 spread_bps -> 再降 refresh_ticks -> 最后小幅提 order_size。
  • 症状B：撤单失败/限频多 -> 先升 refresh_ticks -> 再升 spread_bps -> 暂不动 order_size。
  • 症状C：保证金不足/51008 -> 先降 max_notional_usdt 或 order_size -> 开余额压缩 -> 再降杠杆上限。
  • 症状D：AI单质量差 -> 先升 min_confidence -> 再升 ai_interval_sec -> 再降 ai_depth_frac。
  • 症状E：成交价格劣化 -> 先降 ai_slip_bps -> 再降 price_band_pct -> 必要时提高 min_confidence。
  • 症状F：网格来回打脸 -> 先增 grid_band_pct -> 再减 grid_levels -> 观察后再调 size。

9.2 参数联动关系（核心）

  • spread_bps ↓ 通常要配 refresh_ticks ↑ 或 order_size ↓，否则撤单压力激增。
  • order_size ↑ 需同步 max_notional_usdt ↓ 或 ai_depth_frac ↓，避免一次吃深度。
  • ai_interval_sec ↓ 需配 min_confidence ↑，否则低质量信号过多。
  • grid_levels ↑ 需配 grid_band_pct ↑，否则网格过密导致重挂频繁。
  • twap_slices ↑ 时可适度 interval ↓，但总时长不要过长（影响执行完成率）。

9.3 禁止同时大改的组合

  • 不要同时：spread_bps 大幅下调 + refresh_ticks 大幅下调 + order_size 上调。
  • 不要同时：ai_interval_sec 下调 + min_confidence 下调 + max_notional 上调。
  • 不要同时：grid_band_pct 下调 + grid_levels 上调（会过密）。

9.4 单次调参纪律（强制）

  • 单次最多改 1~2 个参数。
  • 每次改完至少观察 20~30 分钟（高频策略）或 1~2 小时（慢频策略）。
  • 记录“改前值/改后值/异常是否减少”，再进入下一轮。

10. 每一步界面定位速查（1-2-3区）

一句话：改参数=1区；看行情=2区；看挂单/下单=3区；换模式/代理=顶栏；查报错=底栏。

  • 改策略参数：去 1区
  • 看行情/切K线周期：去 2区
  • 看订单簿/挂单/快捷下单：去 3区
  • 换交易对/模式/代理：去 顶栏
  • 查报错关键字：去 底栏日志

11. 风控与故障排查（上线前必读）

一句话：遇到异常先停机再排查；不要在异常状态下“边跑边改”。

9.1 风控四原则

  • 先模拟后实盘。
  • 先保守后均衡再激进。
  • 先止损再收益，先活下来。
  • 先停机再排障，别带病运行。

9.2 常见错误速修

  • 出现 51008：降低名义、开启余额压缩。
  • AI失败：检查 AI_API_BASE / AI_MODEL / AI_API_KEY 或改本地模式。
  • K线不动：检查顶栏连接状态与代理可达性。
  • 连续撤单失败：检查网络、交易对、权限、限频。
  • 策略启动即停：参数越界或风控触发，先看底栏日志关键字。

12. 值班排障SOP（P1 / P2 / P3）

一句话：P1先止损（停+撤）；P2先降风险参数；P3先观察记录，别乱动。

P1（严重）：资金或风控高风险

  • 判定标准：连续下单异常、保证金告警持续、异常成交放大、策略失控。
  • 5分钟应急：停止全部策略 -> 一键撤单 -> 切模拟盘 -> 截图/导出日志。
  • 30分钟恢复：核查 API 权限与账户余额，回滚到保守模板，单策略小仓位重启验证。
  • 当日禁令：未完成复盘前，禁止恢复激进参数。

P2（中等）：功能可用但质量下降

  • 判定标准：撤单失败升高、AI信号质量下降、成交价格劣化。
  • 5分钟应急：提高 refresh_ticks、提高 min_confidence、降低 max_notional。
  • 30分钟恢复：按“参数联动图谱”做单变量回测式调参并记录结果。

P3（轻微）：体验问题或偶发告警

  • 判定标准：偶发网络抖动、偶发单次失败、日志轻微告警。
  • 5分钟应急：观察不急改；确认连接恢复后再继续。
  • 30分钟恢复：汇总出现时间点并做预防性阈值微调。

13. 值班检查清单（打勾版）

一句话：这份清单是“执行纪律”，照着打勾能显著减少误操作与带病运行。

13.1 开盘前（启动前 5~10 分钟）

  • 顶栏模式正确（模拟/实盘）
  • 交易对正确（例：ETH-USDT-SWAP）
  • 连接状态正常（REST 延迟不持续飙高）
  • 代理（如需要）已应用且可用
  • 系统配置已保存，API 权限正确（实盘/模拟匹配）
  • 选用保守/均衡/激进模板已确认（首日建议保守）
  • 紧急停机路径已确认（停止全部策略 + 一键撤单）

13.2 盘中（每 30 分钟巡检一次）

  • 2区行情还在刷新（价格/K线不冻结）
  • 3区挂单不积压（撤单失败不过多）
  • 底栏无“连续重复报错”（连续3次算异常）
  • 风控参数未被随意大改（单次最多改 1~2 个）
  • 账户可用余额/保证金状态正常（无持续 51008）

13.3 收盘后（停机与归档）

  • 停止策略（或停止全部策略）
  • 一键撤单确认挂单清零
  • 导出今日有效模板（如有优化）
  • 记录异常时间点与处理动作（用于复盘）
  • 如为实盘：确认无遗留仓位/挂单（按你的风控要求）

提示：清单是“执行纪律”，能显著减少带病运行与误操作。

16. 新增功能超详细教程（小白一看就会）

一句话：主界面负责“交易操作”，AI 指挥中心负责“过程解释”。看不懂就先按本章从 16.1 到 16.8 走一遍。

16.1 新增了什么（先建立全局认知）

  • 品牌统一：软件名统一为 LeiTingQuantPro（窗口标题、顶栏品牌、手册导出名、日报名等）。
  • Logo 接入：应用图标/托盘图标统一使用你提供的 logo（优先 assets/logo.png）。
  • AI 指挥中心独立窗口：把“过程展示”从主界面迁出，主界面更干净。
  • 多镜头 + 时间线高亮：主镜头/风控镜头/执行镜头轮播，并自动定位对应事件。
  • 小人工作流可视化：时间线内置顶“工位动画”，持续显示当前角色正在做什么。
  • 可解释证据链：每条事件都有“解释/经过/角色/原因”，不是只给技术词。
  • 副屏锁定：可从工具菜单开启“AI 指挥中心锁定到副屏”。

16.2 从哪里打开 AI 指挥中心（一步一步）

  1. 点击顶部菜单 工具。
  2. 点击 打开 AI 指挥中心窗口…。
  3. 若你有副屏：再点 工具 → AI 指挥中心：锁定到副屏（开/关）。
  4. 如果关闭软件重开后窗口位置变化：这是正常现象，可再次点“锁定到副屏”。

注意：主界面不再承载“指挥中心大段演示内容”，这是刻意设计，防止交易页面过载。

16.3 AI 指挥中心每一行怎么读（逐行解释）

  • 总览：显示交易对、策略名、当前状态、最新提示信息。
  • 当前在做什么：把技术状态（如 waiting/deciding）翻译成人话。
  • 管线：预热→采集→模型→解析→过滤→风控→下单→回报，当前步骤会高亮。
  • 产业线：显示整条流程工位和状态灯（G=忙碌、Y=已过站、R=待处理）。
  • 办公室小人：显示当前角色（运维员/行情员/建模师/风控官/交易员…）及动作。
  • 多镜头：切换“主镜头/风控镜头/执行镜头”，用于不同维度盯盘。
  • 导演旁白：把当前阶段转成一句场景化描述，方便向非技术同事解释。
  • 战术建议：根据当前阶段给操作建议（降速/校准/执行跟踪等）。
  • 时间线：按时间记录 AI 事件，自动高亮最关键条目。

16.4 为什么“AI 没工作时”会隐藏很多内容（不是坏了）

  • 当策略不是 AI-LIVE，或状态为 idle 且无事件流时，指挥中心会自动收起高级演示块。
  • 这样做的目的是避免误导用户“看起来很忙但实际没在决策”。
  • 恢复显示的方法：切到 AI-LIVE，勾选启用 AI 实盘决策，启动策略，等待事件流出现。

16.5 预热/采集为什么会慢（如何在界面上看懂）

  • 预热慢的核心：需要先收集 warmup_snapshots 条有效快照，才能进入模型环节。
  • 采集慢的核心：盘口/ticker/candles 任一缺失或超时，都会导致“快照不完整”。
  • 现在时间线“原因”会显示：缺少了哪些数据项（如 orderbook / ticker / candles_1m）。
  • 还会显示预热进度和估计剩余时间，帮助你判断是“正常等待”还是“网络异常”。

新手建议：先把 warmup_snapshots 设小（如3），ai_interval_sec 设 10~15，验证流程跑通后再回归稳健值。

16.6 时间线怎么用来定位问题（实操模板）

  1. 先看最后一条事件的 stage（停在哪一步）。
  2. 再看该条下面的 原因（缺数据/风控拦截/置信度不足/异常）。
  3. 看“经过链路”是否反复在同一个区间循环（例如一直预热->采集）。
  4. 若出现 ordId 相关事件，可回主界面挂单表对应核对。
  5. 若连续出现同类失败，按第12章 SOP 执行：先降风险或先停再查。

16.7 三种常见误解（直接给结论）

  • 误解1：“没看到花里胡哨，就是 AI 没跑。”
    纠正：看状态、时间线和原因，不看特效数量。
  • 误解2：“显示 waiting 就是卡死。”
    纠正：通常是等待下一轮或预热未满；先看“原因”和剩余时间。
  • 误解3：“主界面没显示 NOC 内容是不是丢了。”
    纠正：内容已迁移到独立 AI 指挥中心，主界面故意简洁。

16.8 5 分钟快速上手脚本（给新同事）

  1. 打开软件，确认顶栏交易对正确，模式先模拟盘。
  2. 打开 工具 → 打开 AI 指挥中心窗口。
  3. 1区选 AI-LIVE，勾选启用 AI 实盘决策（先模拟环境验证流程）。
  4. 点“启动策略”，观察指挥中心“总览 + 当前在做什么 + 时间线原因”。
  5. 若提示缺数据：优先检查代理与连接状态；若风控拦截：按建议降速/降名义。
  6. 确认流程跑通后，再进入实盘前检查清单（第13章）。
